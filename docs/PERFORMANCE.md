# Скорость и нагрузка: замеры и исправления (25.10.2026)

Замеры — локально: прод-сборка (`vite preview`), API на Node (`npm run dev:api`), PostgreSQL на той же машине.
На Vercel цифры API будут другими (холодный старт функций, сеть до базы), но соотношение «до/после» сохраняется;
ответы контента и sitemap там дополнительно кэширует CDN (`s-maxage`).

## Скорость страницы (Lighthouse, мобильный профиль, главная)

До исправлений:

| Метрика | Значение |
|---|---|
| Performance | 81 |
| Accessibility / Best practices / SEO | 100 / 100 / 100 |
| First Contentful Paint | 2,9 с |
| Largest Contentful Paint | 3,8 с (элемент — H1, задержка отрисовки 2,7 с) |
| Total Blocking Time / CLS | 0 мс / 0 |

Главные причины: блокирующий CSS Google Fonts (оценка экономии 1,2 с) и тяжёлые картинки (оценка экономии 1,8 МБ: фото 6000×4000 до 1,5 МБ, логотипы до 160 КБ).

Что сделано:
- **Шрифт** Montserrat — свой хостинг (`public/fonts`, вариативный woff2, только латиница и кириллица), `preload` двух основных подмножеств, без запросов к Google Fonts. Из CSP убраны `fonts.googleapis.com` и `fonts.gstatic.com`.
- **Картинки** (`python scripts/optimize-images.py`): фото не больше 1600 px, JPEG q82 progressive, PNG с палитрой, логотипы не шире 640 px. Имена файлов прежние. `public/images/cms` + `public/logos`: 9,2 МБ → 2,2 МБ. Маскот на главной: 1254 px / 159 КБ → 720 px / 63 КБ.

После (прод-сборка, главная): 17 запросов, ≈150 КБ передано, 0 внешних запросов. Повторный прогон Lighthouse не делался.

## Нагрузка на API (autocannon, 10 с)

| Эндпоинт | До | После |
|---|---|---|
| `GET /api/public/content` (50 соединений) | 340 запросов/с, задержка 145 мс (p99 254 мс) | ≈5 900 запросов/с, 8 мс |
| `GET /api/public/content` (100 соединений, ru и kk) | — | ≈5 000 запросов/с, 19 мс (p99 34 мс) |
| `GET /api/sitemap.xml` (100 соединений) | 2 000 запросов/с, 25 мс (50 соединений) | ≈9 600 запросов/с, 10 мс |
| `POST /api/leads` (50 соединений, один IP) | ответ 500 на базе без миграции 0004 | 375 запросов/с, 132 мс; сохраняется 1 заявка, остальные — 201 дубль или 429 лимит |

Что сделано:
- **Кэш публичных ответов** (`server/lib/cache.ts`): контент на каждом языке и sitemap собираются из базы один раз и держатся в памяти (контент — 30 с, sitemap — 5 мин). Любое изменение в админке сбрасывает кэш сразу (`audit()`). Параллельные запросы при пустом кэше ждут одну сборку, а не идут в базу каждый. Ответы с `ETag`, повторный запрос с `If-None-Match` получает 304 без тела.
- **Заявки без падений на старой схеме**: если миграция 0004 не применена, заявка всё равно сохраняется (без источника), вместо ответа 500.
- **Миграции при деплое**: `npm run vercel-build` (`scripts/vercel-build.mjs`) в production-деплое применяет миграции к боевой базе, затем собирает сайт. Preview-деплои базу не трогают; отключить — `SKIP_DB_MIGRATE=1`.
- **Дубли заявок под нагрузкой**: к замку по IP добавлен замок по телефону — одинаковые заявки, отправленные параллельно с разных адресов (IPv4/IPv6, мобильная сеть), сохраняются один раз.

## Как повторить

```bash
npm run build && npx vite preview --port 4173
npx lighthouse http://localhost:4173/ --only-categories=performance --chrome-flags="--headless=new"
npx autocannon -c 100 -d 10 http://localhost:8787/api/public/content
```
